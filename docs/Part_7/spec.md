# PseudoClaude 上下文管理 Spec

## 背景

PseudoClaude 当前以完整对话历史作为每次模型请求的输入。随着用户消息、助手回复、工具调用和工具结果不断累积，请求体会持续变大，最终可能逼近或超过模型上下文窗口，导致长时间任务被迫中断。

在编码类工作流中，体积最大的内容通常不是用户消息，而是工具结果，例如文件读取、搜索、命令输出和 MCP 工具返回的大段文本。用户原始消息承载真实意图，应尽量原文保留；工具结果多半可以通过落盘、预览和重新读取来恢复，因此上下文压缩应优先从工具结果入手。

本阶段为 PseudoClaude 增加两层上下文管理能力。第一层是轻量预防：在每次模型请求前检查工具结果，超过阈值的结果写入会话文件，对话中只保留稳定预览和可重读路径。第二层是重量兜底：当整体历史接近上下文窗口上限时，调用模型生成结构化摘要，压缩较早历史，同时保留近期原文和明确边界提示。两层策略共同保证 PseudoClaude 能在有限 token 预算内连续工作更久，并在需要原文细节时通过工具重新读取，而不是依赖摘要猜测。

## 目标

- G1: PseudoClaude 能在长时间会话中自动控制上下文体积，降低因上下文超限导致请求失败的概率。
- G2: 工具结果是压缩优先对象；用户原始消息默认原文保留，只有在整体兜底压缩中才进入摘要记录。
- G3: 超大工具结果落盘后仍可访问，对话中的替换内容明确告诉模型如何重新读取完整内容。
- G4: 自动压缩和手动压缩共用同一套摘要语义，但触发阈值和安全余量不同。
- G5: 压缩后的对话必须保留足够近期原文，让模型能自然继续当前任务。
- G6: 摘要连续失败时系统进入自动压缩熔断状态，避免反复失败形成死循环。
- G7: 本阶段只采用近似 token 估算，不引入精确 tokenizer 或摘要质量优化系统。

## 功能需求

- F1: 每次模型请求发出前，系统必须先执行轻量预防检查，扫描历史中尚未处理的工具结果。
- F2: 当单个工具结果超过单条阈值时，系统必须把完整内容保存到会话目录中的文件，并把对话里的该工具结果替换为稳定预览。
- F3: 预览内容必须包含原始大小、头部预览、完整文件路径和重读提示，明确告知模型需要完整内容时应使用文件读取工具重新读取。
- F4: 同一个工具结果一旦决定替换，后续请求中必须复用同一份预览文本；同一个工具结果一旦决定保留原文，后续轻量预防不再反复改变该决定。
- F5: 如果工具结果落盘失败，系统必须保留原始工具结果，并允许下一次请求前重新尝试；落盘失败不能中断正常对话流程。
- F6: 当单条消息或同一轮工具结果的合计体积超过聚合阈值时，系统必须按体积从大到小依次落盘工具结果，直到剩余工具结果体积回落到阈值内。
- F7: 轻量预防只做确定性的本地处理，不调用模型，不摘要用户消息。
- F8: 系统必须维护近似 token 估算值，优先锚定最近一次模型返回的真实 usage，并对之后新增内容按字符数比例估算增量。
- F9: 每次模型请求完成后，系统必须用该次请求返回的 usage 更新估算锚点；没有 usage 时不得用虚构数值覆盖已有锚点。
- F10: 轻量预防完成后，如果估算 token 达到自动压缩阈值，系统必须在普通模型请求发出前触发重量兜底摘要。
- F11: 自动压缩阈值必须基于当前上下文窗口计算，并预留摘要输出空间和 13K token 安全余量。
- F12: 用户手动触发压缩时必须无条件进入重量兜底摘要，不受自动阈值限制；手动触发仅使用 3K token 安全余量判断摘要请求自身是否需要更激进的输入裁剪。
- F13: 摘要请求不得携带任何工具定义，也不得允许模型调用工具。
- F14: 摘要 prompt 必须要求模型先写分析草稿，再写正式摘要；系统只保留正式摘要，丢弃分析草稿。
- F15: 正式摘要必须采用固定结构，至少包含：主要请求和意图、关键技术概念、文件和代码位置、错误与修复、问题解决过程、用户消息原文记录、待办任务、当前工作状态、可能的下一步。
- F16: 摘要中的用户消息原文记录必须尽量逐条保留用户原话；如因极端长度无法全部原文保留，必须明确标注发生了裁剪。
- F17: 重量兜底摘要完成后，系统必须保留近期原文，从对话尾部向前选择约 1 万 token 的内容，并且至少保留 5 条消息。
- F18: 近期原文保留不得切断工具调用和对应工具结果之间的配对关系；如果截断点落在配对中间，必须向前扩展到完整配对之前。
- F19: 压缩后的对话必须在摘要和近期原文之间插入一条边界消息，明确提醒模型：摘要不是代码或错误原文，需要文件细节、错误细节、工具结果全文或用户原话时应重新读取相关文件或记录，不要凭摘要脑补。
- F20: 系统必须允许用户通过 TUI 内置命令手动触发压缩；该输入不得作为普通用户消息发送给模型，也不得写入对话历史。
- F21: 手动压缩完成后，TUI 必须显示压缩前后估算 token 的变化；失败时必须显示可理解的错误信息。
- F22: 自动压缩触发时，TUI 必须显示正在压缩的状态提示；压缩完成后显示压缩前后估算 token 的变化。
- F23: 自动摘要连续失败 3 次后，系统必须停止自动触发重量兜底，进入熔断状态。
- F24: 熔断状态只影响自动压缩；用户手动压缩仍可触发重量兜底，并在成功后不受自动熔断阻拦。
- F25: 任意一次自动摘要成功后，自动摘要连续失败计数必须清零。
- F26: 当摘要请求自身过大而失败时，系统必须按较早历史优先的原则裁剪摘要输入并重试；重试仍失败时按一次摘要失败记录。
- F27: 系统必须支持配置或推导当前模型上下文窗口；未显式配置时为已支持 provider 使用合理默认值。
- F28: 所有落盘工具结果必须写入当前会话专属目录；会话目录在进程生命周期内稳定，进程退出后不要求自动清理。
- F29: 压缩功能必须可被测试环境独立验证，不依赖真实网络模型调用来测试轻量预防、token 估算、近期原文选择和熔断行为。

## 非功能需求

- N1: 轻量预防应在每次请求前快速完成；除必要的文件写入外，不应明显拖慢普通交互。
- N2: 压缩状态必须在同一会话内保持稳定，包括工具结果替换决策、落盘路径、usage 锚点和自动摘要失败计数。
- N3: 并发访问压缩状态时不得出现数据竞争，尤其是 TUI 命令路径、主循环请求路径和工具结果回填路径同时访问时。
- N4: 未触发压缩时，现有对话、工具调用、权限模式、Plan/Do 工作流和 provider 请求行为应保持兼容。
- N5: 压缩过程必须可观测，至少能通过事件、日志或 TUI 状态看到触发原因、压缩前估算 token、压缩后估算 token 和落盘工具结果数量。
- N6: 第 1 层落盘失败必须降级处理；第 2 层摘要失败必须向用户或事件流报告，不能导致进程崩溃。
- N7: 摘要内容应偏向任务恢复和事实记录，不应编造文件内容、错误原文或未观察到的代码细节。

## 不做的事

- 不引入精确 tokenizer；本阶段使用 usage 锚点加字符数比例的近似估算。
- 不做摘要质量的机器学习优化、评分回流或多模型比较。
- 不持久化完整对话历史用于跨进程恢复；本阶段只保证当前进程会话内的上下文管理。
- 不自动清理会话落盘目录；保留目录便于调试和人工查看。
- 不压缩或改写用户最新输入；用户手动输入仍按原流程进入任务，除非它是内置命令。
- 不要求摘要完全替代原文；需要精确文件、错误或工具结果细节时必须重新读取。
- 不把所有阈值都暴露成配置；本阶段只要求上下文窗口可配置或可推导。

## 验收标准

- AC1: 构造一个超过单条阈值的工具结果并发起下一次模型请求前检查，观察到完整结果被写入会话目录，对话中只保留包含原始大小、预览、路径和重读提示的替换内容。
- AC2: 对同一个已替换工具结果连续发起两次请求前检查，观察到第二次使用的预览文本与第一次完全一致，且不会重复改写落盘文件。
- AC3: 模拟工具结果落盘失败，观察到该工具结果仍以原文留在对话中，普通模型请求流程不因此中断。
- AC4: 构造多条工具结果合计超过聚合阈值的场景，观察到系统按体积从大到小落盘足够数量的结果，使剩余工具结果体积回到阈值内。
- AC5: 在估算 token 未达到自动阈值时发起请求，观察到只执行轻量预防，不触发摘要请求。
- AC6: 在估算 token 达到 `context_window - 摘要预留 - 13K` 时发起请求，观察到普通模型请求前先完成一次自动摘要。
- AC7: 抓取自动或手动摘要请求，观察到请求不包含任何工具定义，也没有工具调用结果进入摘要输出。
- AC8: 使用包含分析草稿和正式摘要的模拟模型输出，观察到压缩后的对话只保留正式摘要，不保留分析草稿。
- AC9: 检查正式摘要内容，能看到固定结构中的各个部分，并能在用户消息原文记录部分找到压缩前用户消息的原话或明确裁剪标注。
- AC10: 压缩后检查对话尾部，观察到近期原文保留约 1 万 token 且不少于 5 条消息；如果截断区域涉及工具调用，工具调用和对应工具结果没有被拆开。
- AC11: 压缩后检查摘要与近期原文之间，观察到边界消息明确要求需要文件、错误、工具结果或用户原话细节时重新读取，不要凭摘要猜测。
- AC12: 在 TUI 输入手动压缩命令，观察到该输入不作为普通用户消息发送给模型，且触发一次摘要流程。
- AC13: 在估算 token 很低时输入手动压缩命令，观察到系统仍执行一次摘要，不被自动阈值拦截。
- AC14: 手动压缩成功后，TUI 显示压缩前后估算 token 的变化。
- AC15: 自动压缩触发时，TUI 显示正在压缩状态；完成后显示压缩前后估算 token 的变化。
- AC16: 模拟自动摘要连续失败 3 次，观察到第 4 次达到自动阈值时不再自动触发摘要。
- AC17: 在自动压缩熔断后输入手动压缩命令，观察到手动摘要仍会执行。
- AC18: 模拟一次自动摘要成功，观察到连续失败计数被清零，后续达到阈值时自动压缩恢复可用。
- AC19: 连续完成多次真实或模拟模型请求后，观察到 usage 锚点使用最近一次 provider 返回的 usage 更新，而不是简单累加历史 usage。
- AC20: 配置上下文窗口为特定数值后，观察到自动触发阈值随该数值变化；未配置时，已支持 provider 使用默认上下文窗口。
- AC21: 进程启动后触发工具结果落盘，观察到落盘文件位于当前会话专属目录；重启后新会话使用新的目录，旧目录不被自动删除。
- AC22: 使用测试替身验证轻量预防、token 估算、近期原文选择和熔断行为，不需要访问真实 provider 或网络。
