# MCP 客户端 Spec

## 背景

PseudoClaude 已经具备多 provider 流式对话、本地工具系统、Agent Loop、计划模式、系统提示工程化和五层权限控制。Agent 可以在一次请求中多轮调用内置工具，读取、搜索、编辑项目文件并执行命令；权限系统也能在工具真正执行前完成黑名单、沙箱、规则、模式和人在回路确认。

当前能力边界仍固定在内置工具集合中。用户如果希望让 PseudoClaude 使用 GitHub、数据库、内部服务或其它社区工具，只能修改源码并重新编译，工具生态无法通过配置扩展。Model Context Protocol（MCP）提供了一套基于 JSON-RPC 2.0 的标准协议，让客户端可以通过统一握手、工具发现和工具调用流程接入外部 Server 提供的工具。

Part_6 的目标是为 PseudoClaude 增加 MCP 客户端能力：启动时从用户级和项目级配置读取 MCP Server 列表，按 stdio 或 Streamable HTTP 建立连接，发现外部工具，并把它们注册到 PseudoClaude 现有工具中心。Agent 调用时不需要感知工具来自内置实现还是外部 MCP Server；单个 Server 失败不影响其它 Server 和内置工具。

## 目标

- 通过配置声明 MCP Server 列表，让 PseudoClaude 启动时自动发现并注册外部工具。
- 支持本地 stdio 子进程和远程 Streamable HTTP 两种 MCP 传输。
- 按 MCP 的 JSON-RPC 2.0 会话流程完成初始化握手、工具列表读取和工具调用。
- 将远端 MCP 工具适配为 PseudoClaude 现有工具抽象，使 Agent、provider 适配层和 TUI 调用链路保持无感。
- 管理多个 Server 的连接缓存和生命周期，保证单个 Server 失败、超时或调用出错时不会拖垮其它 Server。
- 从用户级和项目级两层配置合并 Server 列表，项目级同名 Server 完整覆盖用户级。
- 本阶段只覆盖 MCP 工具能力，不实现资源、提示词、采样、健康检查或自动重连。

## 功能需求

- F1: 两层配置读取与合并
  系统应从用户级 `~/.PseudoClaude/config.yaml` 和项目级 `<project>/.PseudoClaude/config.yaml` 读取 MCP Server 配置。配置中使用 `mcp_servers` map 声明 Server 列表，每个 key 是 Server 名。两层配置按 Server 名合并；项目级同名 Server 完整覆盖用户级同名 Server，不做字段级深合并。任一层文件缺失时视为空；任一层文件无法读取或格式非法时应跳过该层并给出非致命提示，不阻止其它层配置和内置工具启动。

- F2: Server 配置格式
  每个 Server 必须声明传输类型。`stdio` 类型必须提供 `command`，可选 `args` 和 `env`；`http` 类型必须提供 `url`，可选 `headers`。`env` 和 `headers` 是字符串 map。传输类型缺失、类型不支持或必填字段缺失时，应跳过该 Server 并给出非致命提示，其它 Server 不受影响。

- F3: 环境变量展开
  `stdio` Server 的 `env` 值和 `http` Server 的 `headers` 值应支持 `${VAR}` 形式的宿主环境变量展开。展开只作用于 map 的值，不作用于 Server 名、工具名、`command`、`args` 或 `url`。未定义环境变量展开为空字符串并给出非致命提示；系统不应把密钥明文写回配置文件或输出到日志。

- F4: stdio 传输
  对 `stdio` 类型 Server，系统应在启动发现阶段拉起本地子进程，并通过子进程标准输入和标准输出收发 UTF-8 JSON-RPC 2.0 消息。配置中的 `env` 与宿主环境合并后注入子进程，同名变量以配置值为准。Server 的标准错误应能被用户观察到以便排错。PseudoClaude 退出时应关闭已启动的 stdio 会话并终止对应子进程。

- F5: Streamable HTTP 传输
  对 `http` 类型 Server，系统应以配置的 `url` 作为 MCP endpoint，通过 Streamable HTTP 传输收发 JSON-RPC 2.0 消息。配置中的 `headers` 应随请求发送，用于认证或其它服务端要求。HTTP 连接失败、协议错误或鉴权失败只影响该 Server。

- F6: JSON-RPC 2.0 请求响应配对
  MCP 客户端应按 JSON-RPC 2.0 发送请求、通知和接收响应。带 `id` 的请求必须能与对应响应异步配对；收到错误响应时应保留错误码和可读原因；收到不合法 JSON-RPC 消息时应将其视为该连接或调用的协议错误。并发调用同一 Server 的多个工具时，响应不得因返回顺序不同而错配到其它请求。

- F7: MCP 会话三步流程
  每个 Server 成功建立传输后，应先发送初始化请求并等待初始化响应，随后发送初始化完成通知，再读取工具列表。进入正常工作阶段后，系统应按需发送工具调用请求。初始化、列工具或调用任一阶段失败时，应产生可解释错误；启动阶段失败的 Server 被跳过，调用阶段失败的工具调用以结构化错误结果回灌给模型。

- F8: 工具发现与注册
  系统应把每个成功连接 Server 返回的工具转换为 PseudoClaude 工具中心可注册的工具定义。远端工具的名称、描述和输入参数 schema 应被保留；描述为空时提供可读兜底描述；输入参数 schema 缺失或为空时提供对象类型兜底。注册后的工具应在 Agent 下一次请求模型时与内置工具一起暴露给 provider。

- F9: 工具命名空间
  MCP 工具注册到 PseudoClaude 时应使用稳定命名空间，格式为 `mcp__<server>__<tool>`。命名空间用于避免不同 Server 的同名工具互相覆盖，也避免与内置工具重名。若拼接后的工具名不满足 provider 可接受的工具名字符集，应跳过该工具并提示原因。若同一 Server 返回重复工具名，应保留一个确定结果并提示冲突。

- F10: 工具调用适配
  Agent 调用 MCP 工具时，系统应根据命名空间定位原始 Server 和远端工具名，将模型传入的 JSON 参数作为 MCP 工具参数发送。远端返回的文本内容应按顺序汇总为 PseudoClaude 工具结果内容；远端明确标记的工具错误应映射为工具错误结果；传输错误、协议错误、连接关闭或超时也应映射为结构化工具错误结果，而不是让 Agent Loop 崩溃。

- F11: 非文本内容处理
  本阶段只把远端返回的文本内容回灌给模型。图片、音频、资源链接、嵌入资源或其它非文本内容块不进入工具结果正文；系统应提示这些内容被丢弃，但不得因此让一次原本成功的调用变成致命错误。

- F12: 只读性与权限集成
  如果远端工具声明自身为只读，系统应把该工具归入 PseudoClaude 的只读工具安全等级；未声明或声明无法识别时按有副作用工具处理。MCP 工具应复用现有权限链路：权限规则可以使用 `mcp__<server>__<tool>` 或通配模式匹配；只读 MCP 工具在现有权限模式下按只读类别处理；非只读 MCP 工具按有副作用类别处理。MCP 接入不应要求 provider 适配层承担权限判断。

- F13: 多 Server 失败隔离
  启动时应尝试连接所有配置中的 Server。单个 Server 在连接、初始化、列工具任一阶段失败或超时，只跳过该 Server，不影响内置工具和其它 Server。所有 Server 尝试结束后再进入正常 TUI 会话；进入会话后，本次进程中的工具集合保持稳定，不因后续 Server 状态变化而自动增减。

- F14: 连接缓存与生命周期
  每个成功连接的 Server 会话应被缓存，以便后续工具调用复用同一连接。系统应跟踪所有成功建立的会话，并在 PseudoClaude 退出时统一关闭。关闭某个 Server 卡住或失败时，不应无限阻塞整个程序退出。

- F15: 超时与取消
  Server 启动发现流程和单次工具调用都应有明确超时边界。用户取消当前 Agent 轮次时，正在等待的 MCP 工具调用应响应取消并返回可解释的取消或超时结果；取消不得破坏工具调用 ID 与结果回灌的配对关系。

- F16: 配置示例与文档
  Part_6 文档应说明 `mcp_servers` 配置格式，并包含 stdio 与 HTTP 两类示例。示例中的密钥必须通过 `${VAR}` 引用环境变量，不写入真实 token。

## 非功能需求

- N1: 失败隔离
  任一 MCP Server 的连接失败、初始化失败、列工具失败、调用失败或关闭失败，都不得影响内置工具和其它 MCP Server 的可用性。

- N2: 安全默认
  配置不合法的 Server 被跳过；远端工具只读性缺失或无法识别时按有副作用处理；参数解析失败或协议状态不确定时返回错误或进入权限确认，不静默放行。

- N3: Agent Loop 稳定
  MCP 工具错误应表现为一次工具调用的结构化错误结果，保持多轮 Agent Loop、工具调用 ID 配对、结果顺序、用户取消和后续轮次继续能力不退化。

- N4: 跨 provider 一致
  MCP 工具以 PseudoClaude 工具中心中的普通工具形式暴露。Anthropic、OpenAI 和 OpenAI 兼容接口应看到一致的工具定义和调用结果语义；provider 适配层不应知道某个工具来自 MCP。

- N5: 凭据不泄漏
  环境变量展开后的密钥不应写回配置文件，不应出现在普通日志、TUI 状态、模型回灌内容或错误提示中。错误提示可以说明某个变量未定义，但不输出已展开的敏感值。

- N6: 生命周期干净
  程序退出后不应残留由 PseudoClaude 启动的 stdio Server 子进程；HTTP 会话应尽力通知服务端关闭；关闭流程应有兜底，不因单个 Server 卡住而导致程序无法退出。

- N7: 并发正确
  同一 Server 上多个并发请求的 JSON-RPC 响应必须按请求 ID 正确配对；不同 Server 的连接状态和调用状态互不污染；内部共享状态不得产生数据竞争。

- N8: 范围克制
  本阶段只实现 MCP 工具接入，不扩展资源、提示词、采样、roots、健康检查、自动重连、配置热加载、OAuth 完整流程、审计日志或 Server 端能力。

- N9: 可观测性
  启动阶段应对被跳过的配置层、Server 或工具给出简洁可读的非致命提示。提示应包含 Server 名和失败阶段，但避免输出密钥或大段协议报文。

- N10: 项目规范
  改动应符合 PseudoClaude 现有 Go 代码风格、配置风格和测试组织。既有测试应继续通过，新增 MCP 行为应有针对配置、协议配对、工具适配、失败隔离和生命周期的测试覆盖。

## 不做的事

- 不实现 MCP resources、prompts、sampling、roots 或其它非工具能力。
- 不实现 MCP Server 健康检查、自动重连、退避重试或运行时恢复连接。
- 不实现配置热加载；新增、删除或修改 MCP Server 后需要重启 PseudoClaude。
- 不实现 OAuth 或浏览器登录流程；HTTP 鉴权仅通过配置 headers 注入已有 token。
- 不支持除 stdio 和 Streamable HTTP 之外的传输。
- 不把非文本 MCP 内容块转换为图片展示、文件落盘或资源读取。
- 不在本阶段为 MCP 工具增加专用黑名单、网络访问控制、资源配额或审计日志。
- 不改变 PseudoClaude 的 provider 协议解析、模型路由、对话历史格式或现有内置工具行为。
- 不把用户级和项目级 `mcp_servers` 做字段级深合并；同名 Server 始终由项目级完整覆盖用户级。
- 不展开 `command`、`args`、`url`、Server 名或工具名中的环境变量。

## 验收标准

- AC1: 配置合并
  同时存在用户级和项目级配置时，系统读取两层 `mcp_servers` 并按 Server 名合并；项目级同名 Server 完整覆盖用户级；缺失配置文件视为空，不影响启动。（F1）

- AC2: 配置降级
  任一配置层 YAML 格式非法或读取失败时，该层被跳过并出现非致命提示；其它层 Server 和内置工具仍正常可用。（F1, N1, N9）

- AC3: 字段校验
  `stdio` 缺少 `command`、`http` 缺少 `url`、传输类型缺失或不支持时，对应 Server 被跳过并提示原因，其它 Server 不受影响。（F2, N2）

- AC4: 环境变量展开
  `env` 和 `headers` 的 `${VAR}` 被展开为宿主环境变量；未定义变量展开为空并提示；`command`、`args`、`url`、Server 名和工具名中的 `${VAR}` 保持字面量。（F3, N5）

- AC5: stdio Server 接入
  配置一个可用 stdio MCP Server 后，PseudoClaude 能启动子进程、完成初始化、列出工具并注册；退出 PseudoClaude 后该子进程不残留。（F4, F7, F8, F14, N6）

- AC6: HTTP Server 接入
  配置一个可用 Streamable HTTP MCP Server 后，PseudoClaude 能完成初始化、列出工具并注册；配置的 headers 出现在请求中；HTTP 连接失败只跳过该 Server。（F5, F7, F8, N1）

- AC7: JSON-RPC 配对
  对同一 Server 并发发起多个带 ID 的请求时，即使响应乱序返回，每个响应也回到正确调用；错误响应保留为对应调用的错误结果。（F6, N7）

- AC8: 会话三步流程
  每个成功 Server 都按初始化握手、初始化完成通知、列工具、按需调用工具的顺序工作；初始化或列工具失败的 Server 不进入工具注册。（F7）

- AC9: 工具注册与命名空间
  远端工具注册后的名称符合 `mcp__<server>__<tool>`；不同 Server 的同名工具不冲突；非法工具名被跳过并提示；描述和输入 schema 可被 provider 正常消费。（F8, F9）

- AC10: 工具调用结果
  MCP 工具调用成功时，远端文本内容按顺序汇总进工具结果；远端标记错误、协议错误、连接断开或调用超时时，都以结构化错误结果回灌给模型，Agent Loop 继续。（F10, N3）

- AC11: 非文本内容处理
  远端返回文本和非文本混合内容时，模型只收到文本内容；非文本内容被丢弃并有可观察提示；调用不会因非文本内容存在而崩溃。（F11）

- AC12: 权限复用
  声明只读的 MCP 工具在现有权限模式下按只读工具处理，未声明只读的 MCP 工具按有副作用工具处理；权限规则可匹配 `mcp__<server>__<tool>` 和 `mcp__<server>__*`；provider 适配层无需修改权限逻辑。（F12, N2, N4）

- AC13: 失败隔离
  同时配置一个失败 Server 和一个可用 Server 时，失败 Server 的错误可见但不阻止可用 Server 工具注册，也不影响内置工具使用。（F13, N1）

- AC14: 工具集合稳定
  PseudoClaude 进入 TUI 后，本次进程暴露给模型的工具集合为内置工具加启动时成功发现的 MCP 工具；Server 后续掉线不会自动新增或删除工具定义。（F13）

- AC15: 生命周期关闭
  正常退出或致命错误收尾时，所有已建立 MCP 会话都会被关闭；关闭某个 Server 卡住时，程序仍能在兜底时间内退出。（F14, N6）

- AC16: 超时与取消
  Server 启动发现和单次工具调用卡住时会在超时后返回；用户取消当前轮时，等待中的 MCP 调用被取消或返回错误，后续会话仍可继续。（F15, N3）

- AC17: 凭据安全
  配置示例和文档不包含真实 token；运行时提示不输出已展开的 header 或 env 敏感值；模型回灌内容不包含配置中的密钥。（F3, F16, N5）

- AC18: 不破坏既有能力
  没有 MCP 配置时，PseudoClaude 行为与 Part_5 完成后的行为一致；现有 provider、Agent Loop、计划模式、权限系统、内置工具和 TUI 测试继续通过。（N3, N4, N10）

- AC19: 范围边界
  本阶段没有实现 resources、prompts、sampling、健康检查、自动重连、配置热加载或 OAuth 流程；相关配置或协议能力不会被误暴露为可用功能。（N8）

- AC20: 文档完整
  Part_6 文档包含 `mcp_servers` 的用户级和项目级配置说明、stdio 示例、HTTP 示例、环境变量展开规则和本阶段不做事项。（F16）
