# PseudoClaude 项目记忆与会话恢复 Spec

## 背景

PseudoClaude 已经具备基础终端对话、工具调用、权限控制、MCP 工具接入和单进程内上下文压缩能力。Part 7 解决的是“同一个运行进程里上下文越来越长怎么办”：超大工具结果可以落盘，历史可以在接近上下文窗口时被摘要压缩。但这些能力仍然偏向当前会话，一旦进程退出或用户隔天回来，Agent 仍需要用户重新说明项目规范、个人偏好、上次工作状态和重要参考资料。

真实编码工作并不是一次性对话。用户会长期在同一个项目里反复协作，有稳定的代码风格、工具偏好、项目约定、未完成事项和反复被纠正过的行为模式。如果每次启动都从零开始，Agent 会显得“失忆”：既浪费上下文，也容易重复犯错。

本阶段为 PseudoClaude 增加跨会话的分层记忆能力：项目指令文件提供用户手写的静态规范，会话 JSONL 存档提供可恢复的工作记忆，自动笔记提供逐步演化的长期记忆。三层机制共同目标是让新会话启动时就像“已经读过这个项目和用户偏好”，并在中断后能平滑恢复到可继续工作的状态。

## 目标

- G1: 新会话启动时自动加载项目指令和记忆索引，让 Agent 从第一轮请求就能遵循项目规范、了解用户偏好和关键项目知识。
- G2: 项目指令文件支持项目级、项目配置级、用户级三层加载；高优先级内容排在前面，并支持受控的 `@include` 文件引用。
- G3: 会话历史以 JSONL 追加写入磁盘，不单独维护 meta 文件；需要 ID、标题、消息数、模型、更新时间等信息时直接扫描 JSONL 计算。
- G4: 会话恢复能容忍常见异常，包括坏行、未闭合工具调用、恢复后上下文超限、长时间暂停和过期会话清理。
- G5: 自动笔记按用户偏好、纠正反馈、项目知识、参考资料四类存储，用户级与项目级分开管理。
- G6: 每轮 Agent Loop 自然停下后异步更新记忆，不阻塞用户继续输入；去重、合并和是否写入由 LLM 根据现有索引判断。
- G7: 请求处理前注入记忆索引，而不是等模型需要时再检索；索引控制在 200 行 / 25KB 以内，保持约 2-3K tokens 的轻量上下文成本。
- G8: 本阶段不引入向量数据库、RAG 检索或团队记忆同步，为后续章节保留空间。

## 功能需求

### 项目指令文件

- F1: 系统启动时按三层路径查找项目指令文件：项目根目录、项目根目录下的 `.PseudoClaude/`、用户目录下的 `~/.PseudoClaude/`。存在则加载，缺失则跳过。
- F2: 三层指令按优先级拼接：项目根目录最高，项目 `.PseudoClaude/` 次之，用户目录最低。高优先级内容必须排在前面，并用清晰分隔标记区分来源，帮助模型优先遵循更局部的约定。
- F3: 指令文件为用户手写 Markdown，用于记录技术栈、代码规范、项目约定、注意事项、工作流偏好和禁止事项。系统不得要求用户使用特殊 frontmatter 才能生效。
- F4: 指令文件支持独占行形式的 `@include <relative_path>` 引用。引用路径相对当前指令文件所在目录解析，展开时用被引用文件内容替换该行。
- F5: `@include` 必须限制最大嵌套深度。超过深度时保留可见警告并跳过继续展开，避免无限递归或过大的指令上下文。
- F6: `@include` 必须维护当前展开链路的 visited 集合。检测到环路时跳过该引用，并在加载结果中保留可见警告。
- F7: `@include` 必须拦截跳出允许根目录的路径。项目级和项目配置级文件只能引用项目目录内文件，用户级文件只能引用用户配置目录内文件。
- F8: 不符合独占行语法的 `@include` 文本保持原文，不作为引用处理。
- F9: 缺失的 include 文件不应中断启动；不可读取或疑似二进制的 include 文件应跳过并保留可见警告。
- F10: 指令加载在进程启动时执行一次，加载结果在当前进程生命周期内稳定。运行期间不做文件监听或热更新。
- F11: 加载后的项目指令必须进入系统提示的自定义指令区域；未找到任何指令文件时，该区域为空且不影响现有对话流程。

### 会话存档

- F12: 每个会话必须拥有唯一会话 ID，格式为 `YYYYMMDD-HHMMSS-xxxx`，其中前半部分取会话创建时的本地时间，后缀用于避免同秒碰撞。
- F13: 每个会话写入项目会话目录下的独立子目录。该目录同时容纳 `conversation.jsonl` 和本会话相关的工具结果落盘文件，保证会话恢复和上下文压缩引用同一个会话空间。
- F14: 会话历史使用 JSONL 追加写入，每条消息一行 JSON。追加失败不得篡改已有内容；进程崩溃最多只允许丢失或损坏最后一行。
- F15: JSONL 行必须包含消息角色、写入时间和必要内容字段；助手工具调用、工具结果、模型信息、压缩标记等扩展信息必须能在同一格式中表达。
- F16: 系统不维护单独 meta 文件。会话列表所需的标题、消息数、模型标签、最后更新时间、文件大小等信息必须通过扫描 `conversation.jsonl` 和文件系统信息计算。
- F17: 用户消息、助手消息、工具调用和工具结果被加入对话历史时，必须同步追加到当前会话 JSONL。
- F18: 当现有上下文压缩机制替换整段对话历史时，JSONL 必须写入可识别的压缩边界；恢复时只加载最后一个压缩边界之后的有效历史。
- F19: JSONL 写入必须支持主 Agent Loop、工具结果回填、压缩流程和未来 TUI 路径的并发访问，避免交错写入破坏行结构。
- F20: 当前会话结束或进程退出时，应关闭会话写入资源；异常退出时依赖追加写和逐行恢复保证最大限度可恢复。

### 会话恢复

- F21: TUI 必须提供会话恢复入口，用户可在空闲状态打开历史会话列表并选择一个会话恢复。
- F22: 会话列表扫描项目会话目录下所有有效 JSONL 会话，按最近更新时间倒序展示。
- F23: 会话列表每项至少展示可读标题、相对更新时间、消息数和文件大小；如果 JSONL 中能推导出模型信息，也应展示模型标签。
- F24: 会话标题来自第一条有效用户消息，过长时截断。不存在有效用户消息的会话应显示兜底标题。
- F25: 恢复读取 JSONL 时必须逐行解析。解析失败的坏行跳过，不影响其余有效行恢复。
- F26: 如果恢复后的末尾存在助手工具调用但缺少对应工具结果，系统必须截断到该助手工具调用之前，避免模型看到悬空工具调用。
- F27: 如果 JSONL 中存在压缩边界，恢复时只使用最后一个压缩边界之后的消息，避免旧压缩前历史重复进入上下文。
- F28: 恢复完成前必须估算上下文体积。如果超过当前模型可用窗口阈值，系统必须先执行一次上下文压缩，再进入可对话状态。
- F29: 如果待恢复会话最后一条有效消息距离当前时间超过 6 小时，恢复后必须在对话末尾插入一条时间跨度提醒，提示部分上下文可能过时，需要时重新读取文件或重新确认外部状态。
- F30: 恢复成功后，当前会话切换到被恢复会话：后续新消息追加到同一个 JSONL，工具结果也落到同一会话目录。
- F31: 恢复过程中必须向用户展示加载、失败或成功状态；恢复失败不得破坏当前新会话。
- F32: Agent 正在运行时不得切换会话；恢复选择界面打开时不得同时发起新的 Agent Run。
- F33: 启动后应定期或后台清理 30 天以上的过期会话目录。清理失败的单个会话不得影响启动或其他会话。
- F34: 过期判断只对符合新会话 ID 格式且能解析出时间戳的目录生效；无法识别的旧目录不应被自动删除。

### 自动笔记

- F35: 自动笔记分为四类：用户偏好、纠正反馈、项目知识、参考资料。
- F36: 项目级笔记与用户级笔记必须分开存储。项目级用于当前项目相关知识和参考资料，用户级用于跨项目通用偏好和纠正反馈；具体归属由记忆更新请求中的 LLM 判断。
- F37: 每条笔记保存为一个独立 Markdown 文件，带 frontmatter，至少记录类型、标题、创建时间和更新时间。
- F38: 每级记忆目录维护一份索引文件，索引每行是一条笔记摘要，包含类型、标题和一句话描述。
- F39: 索引文件必须控制在 200 行 / 25KB 以内。超限时，记忆更新流程应通过合并、淘汰或压缩摘要来恢复到限制内。
- F40: 处理用户请求前，系统必须读取项目级和用户级索引并注入系统提示；项目级索引排在用户级索引前。
- F41: 注入系统提示的是索引内容，不是所有笔记全文。模型如果需要完整笔记，可通过文件读取工具读取对应 Markdown 文件。
- F42: 如果索引拼接后仍超过 25KB，注入前必须截断，并保留清晰的截断标记。
- F43: 每轮 Agent Loop 自然停下后，也就是模型最终回复没有继续发起工具调用并完成对用户的最终响应后，系统必须异步发起一次记忆更新。
- F44: 记忆更新异步执行，不阻塞下一轮用户输入，也不得修改当前对话历史。
- F45: 记忆更新请求必须包含本轮关键对话片段和现有项目级、用户级索引，供 LLM 判断是否需要新增、更新、合并或删除笔记。
- F46: 记忆更新请求不得携带工具定义，也不得允许模型调用工具。
- F47: 记忆更新结果必须是结构化操作列表，能表达创建、更新、删除和无变化。空列表表示无需更新。
- F48: 去重和合并判断交给 LLM 完成。系统负责提供索引上下文、校验操作格式、限制文件路径和执行安全的文件写入。
- F49: 自动笔记文件名必须可预测且安全，只允许落在对应记忆目录内，不能通过 LLM 返回的路径跳出目录。
- F50: 记忆更新失败，包括模型错误、结果格式错误、文件写入失败或索引更新失败，都不得影响主会话；系统只记录可诊断信息。
- F51: 记忆更新完成后，后续请求应使用最新索引；已经发出的模型请求不需要 retroactively 更新。

### 集成与生命周期

- F52: 新会话启动流程必须在首轮模型请求前完成项目指令加载、记忆索引加载、会话目录初始化和 JSONL 写入器初始化。
- F53: 系统提示必须同时支持自定义指令和长期记忆两个可选区域。两者为空时，现有固定系统提示行为保持兼容。
- F54: 项目指令、长期记忆和运行环境信息的注入顺序必须稳定，避免同一输入在不同启动中产生不可预测的优先级。
- F55: 会话恢复、上下文压缩、工具结果落盘和 JSONL 存档必须共享同一个会话身份，避免恢复后工具结果路径指向错误会话。
- F56: 自动记忆不得读取或写入会话 JSONL 之外的无关项目文件，除非用户或模型后续通过正常工具流程显式读取。
- F57: 所有新增能力必须能在没有项目指令、没有 memory 目录、没有历史 sessions 目录的全新项目中静默降级并正常启动。

### TUI 可见性命令

- F58: TUI 必须提供 `/memory` 本地命令。该命令不发送给模型，不写入 conversation JSONL，只展示当前 Agent 会使用的长期记忆索引。
- F59: `/memory` 展示前应刷新 memory 索引，内容包含项目级记忆和用户级记忆；两者均为空时展示明确空状态。
- F60: `/resume` 的选择界面应采用与权限 allow 面板一致的轻量选择交互，而不是完整列表页面。用户可用上下键、数字键选择、Enter 恢复、Esc 取消。
- F61: `/resume` 选择面板至少展示会话标题、相对更新时间、消息数、文件大小和模型标签；会话较多时保留最近若干项，优先保证界面可读。
- F62: `/memory` 和 `/resume` 都必须在 Agent 运行中或权限审批中拒绝切换状态，并给出等待当前任务完成的提示。

## 非功能需求

- N1: 启动加载必须足够快。没有大量历史会话时，项目指令和记忆索引加载不应造成明显启动卡顿；过期清理应放在后台执行。
- N2: JSONL 追加写入应以可靠性优先，保证每条完整写入的行可独立解析；写入失败要可诊断但不应直接终止 Agent 运行。
- N3: 恢复逻辑必须保守处理异常。遇到不完整、损坏或无法理解的局部内容时，优先跳过或截断局部内容，而不是猜测修复。
- N4: 新增记忆注入不应破坏现有权限模式、Plan/Do 工作流、MCP 工具注册、上下文压缩和 provider 请求流程。
- N5: 自动笔记应尽量记录稳定事实和明确偏好，避免把临时任务状态、模型猜测或未验证内容长期保存。
- N6: 文件路径安全必须严格。指令 include、记忆文件操作和会话恢复都不得允许相对路径逃逸到预期目录之外。
- N7: 核心逻辑必须可测试。指令加载、JSONL 扫描、恢复异常处理、过期清理、记忆索引拼接、结构化记忆操作执行都应能脱离真实网络模型调用验证。
- N8: 记忆索引注入必须保持小而稳定，目标是不超过约 2-3K tokens，不把长期记忆变成新的上下文膨胀来源。
- N9: 错误隔离必须清晰。项目指令加载失败、记忆更新失败、单个会话清理失败、单行 JSONL 损坏都不能拖垮主会话。

## 不做的事

- 不做向量数据库、embedding、RAG 检索或语义召回；本阶段只注入轻量索引。
- 不做团队记忆同步、云端同步或跨机器共享。
- 不做启动时自动恢复最近会话；启动默认创建新会话，恢复由用户显式触发。
- 不做多个会话合并、分支会话管理或会话重命名。
- 不做指令文件热更新；运行期间修改指令文件要等下次启动生效。
- 不做笔记全文自动注入；长期记忆默认只注入索引。
- 不做记忆质量评分、A/B prompt 优化或用户反馈训练闭环。
- 不清理无法解析为新格式 ID 的旧会话目录，避免误删用户数据。
- 不把 Part 7 的上下文压缩策略改造成新的摘要系统；本阶段只在恢复超限时复用现有压缩能力。

## 验收标准

- AC1: 在项目根、项目 `.PseudoClaude/`、用户 `~/.PseudoClaude/` 各放一份指令文件后启动，首轮模型请求的自定义指令区域包含三份内容，且项目根内容排在最前。
- AC2: 只存在一份项目指令文件时启动，加载成功且缺失层级不会产生用户可见错误。
- AC3: 指令文件中使用独占行 `@include` 引用同目录下 Markdown 文件，加载结果中该行被引用文件内容替换。
- AC4: 构造超过最大深度的 include 链，加载结果不继续展开超限文件，并包含可见深度警告。
- AC5: 构造 include 环路，加载结果跳过重复引用，并包含可见环路警告。
- AC6: 在项目指令中引用项目目录外路径，加载结果不包含外部文件内容，并包含路径越界警告。
- AC7: 启动新会话后，项目会话目录下出现符合 `YYYYMMDD-HHMMSS-xxxx` 格式的会话目录。
- AC8: 发送一条用户消息并获得助手回复后，当前会话 `conversation.jsonl` 至少包含对应 user 和 assistant 行，且每行都是可独立解析的 JSON。
- AC9: 不存在单独 meta 文件时，会话列表仍能通过扫描 JSONL 展示标题、消息数、更新时间和文件大小。
- AC10: 模拟 JSONL 最后一行损坏，恢复时坏行被跳过，其余有效消息正常恢复。
- AC11: 模拟 JSONL 末尾存在未配对的助手工具调用，恢复后该工具调用被截断，最终历史不包含悬空工具调用。
- AC12: 在 JSONL 中存在压缩边界时恢复，会话只加载最后一个压缩边界之后的消息。
- AC13: 构造恢复后估算 token 超限的会话，选择恢复后系统先执行一次压缩，再进入空闲可对话状态。
- AC14: 恢复一个最后消息距当前超过 6 小时的会话，恢复后的对话末尾出现时间跨度提醒。
- AC15: 恢复完成后发送新消息，新消息追加到被恢复会话的同一个 JSONL 文件。
- AC16: Agent 正在运行时尝试恢复会话，系统拒绝切换并提示等待当前任务完成。
- AC17: 创建一个 31 天前的新格式会话目录，启动后后台清理删除该目录；创建无法解析的新格式之外目录，启动后不被自动删除。
- AC18: 对话中表达明确用户偏好后，Agent 最终回复完成且无继续工具调用，后台记忆更新创建或更新对应用户级笔记。
- AC19: 对话中确认项目事实或参考资料后，后台记忆更新创建或更新对应项目级笔记。
- AC20: 新建或更新笔记后，对应级别索引文件出现类型、标题和一句话描述。
- AC21: 索引文件存在时启动新会话，首轮模型请求的长期记忆区域包含项目级索引和用户级索引，且项目级在前。
- AC22: 构造超过 25KB 的索引，注入系统提示前被截断，并包含清晰截断标记。
- AC23: 模拟记忆更新 LLM 返回重复或相似笔记的合并操作，系统按结构化操作更新文件和索引，不产生路径越界写入。
- AC24: 模拟记忆更新失败，主会话仍可继续发送下一条消息，失败只留下可诊断记录。
- AC25: 没有项目指令、没有 memory 目录、没有 sessions 目录的全新项目能正常启动、创建新会话并完成一次普通对话。
- AC26: 恢复后的会话触发工具结果落盘时，落盘文件位于同一个会话目录下，预览中的路径可被文件读取工具重新读取。
- AC27: 输入 `/memory` 后，TUI transcript 展示当前项目级和用户级记忆索引；如果存在用户画像，用户能直接看到该记录。
- AC28: 输入 `/memory` 不增加 conversation 长度，不追加 user JSONL 消息，也不触发模型请求。
- AC29: 输入 `/resume` 后出现与 allow 相似的轻量选择面板；上下键、数字键和 Enter 能选择并恢复会话，Esc 能取消。
