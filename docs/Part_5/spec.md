# 权限系统 Spec

## 背景

PseudoClaude 已经完成了多 provider 流式对话、本地工具系统、Agent Loop、计划模式和系统提示工程化。模型现在可以在一次用户请求中多轮“思考 -> 调工具 -> 看结果 -> 继续调整”，也能在计划模式下只使用只读工具完成探索和规划。

当前工具执行链路仍缺少统一的执行前权限闸门。文件类工具虽然围绕当前工作目录进行路径规整，但还没有形成可配置、可解释、可交互确认的权限系统；命令执行工具能够运行任意本地命令，缺少不可配置的危险命令硬拦截；规则、权限模式和人在回路尚未串成一个一致的判定流水线。随着 Agent Loop 具备连续自主执行能力，这会让“能自己干活”与“在安全边界内干活”之间出现明显缺口。

Part_5 要给 PseudoClaude 加上一套五层防御的权限系统：危险命令黑名单、路径沙箱、可配置规则、多档权限模式、人在回路确认。一次工具调用在真正执行前依次穿过这些层，任一层给出明确 Allow 或 Deny 即短路；规则未命中时，由权限模式给出默认 Allow 或 Ask；落到 Ask 时交给用户确认。权限被拒绝时，系统把结构化拒绝结果回灌给模型，而不是终止 Agent Loop，让模型有机会换一种安全策略继续完成任务。

## 目标

- 建立统一的工具执行前权限判定流水线，按“黑名单 -> 沙箱 -> 规则引擎 -> 权限模式 -> 人在回路”的顺序逐层短路。
- 对已知高危命令提供不可配置关闭的黑名单硬拦截，任何规则或权限模式都不能放开。
- 对文件类工具执行路径沙箱，确保读写和搜索范围限定在项目目录内，并通过符号链接解析防止逃逸。
- 支持用户级、项目级、本地级三层规则配置，以“工具名(模式)”声明 allow 或 deny，并按就近优先级判断。
- 提供 strict、default、acceptEdits、bypassPermissions 等整体权限模式；模式只作为规则未命中时的默认策略，不覆盖显式规则、黑名单或沙箱。
- 当系统无法自动判定时暂停 Agent Loop，把待执行调用交给用户确认，并支持本次、本会话、永久三种放行范围。
- 被拒绝的工具调用以结构化错误结果进入工具回灌，保持 Agent Loop、工具结果配对和对话历史合法。
- 本章只覆盖本地工具权限，不实现网络请求限制、资源配额或审计日志。

## 功能需求

- F1: 危险命令黑名单
  系统应在命令执行类工具真正运行前，用一组内置正则匹配待执行命令。命中黑名单即判定为 Deny，并返回结构化拒绝结果。黑名单是最高优先级防线，不受用户规则、项目规则、本地规则、会话临时规则或任何权限模式影响；即使处于完全放行模式，黑名单命中的命令也必须被拦截。黑名单用于拦截已知高危模式，例如递归强删根目录或家目录、写块设备、格式化文件系统、重定向覆盖磁盘设备、明显 fork 炸弹等。黑名单是启发式防御，不承诺穷尽所有危险命令，且本章不提供配置关闭或扩展能力。

- F2: 路径沙箱
  系统应对带路径参数的文件类工具执行沙箱检查，确保读、写、编辑、按模式找文件和搜内容的目标范围都落在项目根目录内。检查时必须先把输入路径规整为绝对路径，再解析符号链接，最后做项目根前缀判断，防止通过软链接逃逸。对于尚不存在的新建目标，应解析最近的已存在祖先目录后再判断，不因目标文件或中间目录不存在而误拒项目内路径。路径逃出项目根时判定为 Deny。命令执行类工具不做路径沙箱，因为任意命令的文件访问无法可靠静态解析。

- F3: 可配置规则
  系统应支持用“工具名(模式)”声明 allow 或 deny 规则。工具名使用面向用户的友好名：Bash、Read、Write、Edit、Glob、Grep，并映射到 PseudoClaude 的内置命令执行、读文件、写文件、编辑文件、按模式找文件、搜内容工具。不带模式段时，规则匹配该工具的全部调用。模式段支持精确匹配和 glob 匹配；命令执行类工具匹配完整命令串，文件类工具匹配项目相对路径。`*` 匹配任意字符序列，`**` 的跨目录语义仅用于文件路径；对命令串而言 `**` 不具有特殊跨目录语义。一次调用在规则层只能得到 allow、deny 或未命中三种结果。

- F4: 三层规则配置与优先级
  系统应从用户级、项目级、本地级三层 YAML 配置读取规则和可选默认权限模式。规则判断优先级为本地级高于项目级，项目级高于用户级；从高到低逐层判断，就近命中即停止。同一层内 deny 优先于 allow。配置文件缺失视为空规则集；配置文件格式错误时，该文件降级为空规则集，不导致权限引擎构造失败，不额外放开任何权限，也不中断会话。启动默认权限模式按本地级、项目级、用户级的优先级读取；都未配置时使用 default。

- F5: 权限模式兜底
  系统应提供多档权限模式，用于规则未命中时的默认裁决。模式只作为兜底策略，不覆盖黑名单、沙箱或显式 allow/deny 规则。权限模式按工具类别给出 Allow 或 Ask，不直接给出 Deny；Deny 只能来自黑名单、沙箱、显式 deny 规则或人在回路拒绝。工具类别分为只读、文件写、命令执行。默认矩阵如下：

  | 模式 | 只读 | 文件写 | 命令执行 |
  | --- | --- | --- | --- |
  | strict | Ask | Ask | Ask |
  | default | Allow | Ask | Ask |
  | acceptEdits | Allow | Allow | Ask |
  | bypassPermissions | Allow | Allow | Allow |

  既有计划模式仍作为计划工作流存在：计划模式只向模型暴露只读工具，并注入计划提醒；如果防御性地遇到文件写或命令执行请求，应按 Ask 处理，而不是静默放行。

- F6: 五层判定流水线
  一次工具调用在真正执行前应依次经过黑名单、路径沙箱、规则引擎、权限模式兜底、人在回路五层。任一层给出 Allow 或 Deny 即短路返回，不进入后续层。黑名单只对命令执行类工具生效；沙箱只对文件类工具生效；不适用的层视为未拦截并继续下一层。规则未命中时才进入权限模式兜底；权限模式返回 Ask 时才进入人在回路。

- F7: 人在回路确认
  当权限判定落到 Ask 时，系统应暂停当前 Agent Loop 的工具执行，向用户呈现待确认的工具调用，包括工具名、关键参数预览、触发确认的原因和可选操作。用户可选择允许本次、允许本会话、永久允许或拒绝本次。允许本次只影响当前调用；允许本会话写入会话级临时 allow 规则，当前会话后续调用可复用；永久允许写入本地级配置，跨会话生效；拒绝本次返回 Deny。永久允许生成精确匹配规则，不自动泛化为 glob 规则。等待确认期间，用户应能取消当前轮，取消后历史仍保持合法。

- F8: 会话级临时规则
  系统应维护会话级临时规则，专门承载人在回路的“允许本会话”选择。会话级规则优先于本地级、项目级和用户级规则；同一层仍保持 deny 优先于 allow。会话级规则只存在于当前程序会话内，不写入磁盘，不跨重启保留。本章不提供手动编辑会话规则的 UI，只由人在回路生成。

- F9: 运行时权限模式切换
  用户应能在会话中切换权限模式，切换只影响后续工具调用的模式兜底裁决，不改变已加载规则，也不重新解释已经执行或已经拒绝的调用。当前权限模式应在 TUI 中常驻可见。模式跨轮保持，不因一次模型回复结束而重置。既有 `/plan` 与 `/do` 工作流继续可用：进入计划工作流时只暴露只读工具，退出计划并执行时回到可执行工具集。

- F10: 拒绝不中断 Agent Loop
  任何层产生 Deny 时，系统应把拒绝包装成结构化工具结果，包含拒绝来源和可读原因，并按原工具调用 ID 回灌给模型。拒绝不应终止 Agent Loop；模型应能看到拒绝结果并调整策略。同一批多个工具调用中，被拒绝和被允许的调用应各自独立处理，结果按原调用顺序和调用 ID 正确配对。

- F11: 跨 provider 一致
  权限判定发生在 Agent 编排层，在调用 provider 之后、执行本地工具之前完成。Anthropic、OpenAI 及 OpenAI 兼容接口应看到一致的权限行为。权限系统不依赖 provider 协议，不要求修改 provider 的工具调用解析语义。

- F12: 安全默认
  对未知工具、参数无法解析、路径无法规整、工具类别无法判定等不确定情形，系统应采用安全默认：不能静默放行。未知或类别不明的工具按需要确认或拒绝处理；参数无法解析导致无法完成黑名单、沙箱或规则判断时，返回结构化拒绝或进入人工确认，而不是直接执行。

## 非功能需求

- N1: 黑名单不可绕过
  危险命令黑名单必须是权限流水线的最高优先级防线。不存在任何配置项、规则层级、会话临时规则、权限模式或人在回路选择能放开黑名单命中的命令。

- N2: 沙箱防逃逸
  路径判断必须遵循“绝对化 -> 解析符号链接 -> 前缀比对”的顺序。软链接指向项目外部时必须判 Deny。对尚不存在的目标，应基于最近已存在祖先目录完成解析，避免项目内新建路径被误拒，同时防止通过项目内软链接目录写到项目外。

- N3: 权限检查不破坏 Agent Loop
  权限系统接入后，现有 Agent Loop 的多轮编排、工具结果回灌、工具调用 ID 配对、用户取消、工具错误恢复、历史合法性和计划模式提醒不应退化。权限拒绝应表现为一次工具调用的错误结果，而不是整个 Loop 的致命错误。

- N4: 只读并发不退化
  只读工具在规则或模式明确 Allow 时仍可按现有机制并发执行。权限检查不应把所有只读调用强制串行化。只有需要人在回路确认的调用才暂停等待用户决策。

- N5: 人在回路可取消、不死锁
  等待用户决策期间，用户应能取消当前轮。取消后不得泄漏阻塞 goroutine，不得造成 TUI 死锁，不得破坏持久对话历史中的角色顺序或工具调用与工具结果配对关系。

- N6: 配置安全降级
  三层配置文件缺失、读取失败或格式非法时，系统应降级为安全默认，不 panic，不中断会话，不因为解析失败而额外放开权限。配置错误可以被呈现为非致命提示，但不能污染普通模型回答。

- N7: 跨 provider 稳定
  权限判定与 provider 协议解耦。Anthropic、OpenAI 和 OpenAI 兼容 base URL 的工具调用，只要进入同一 Agent 工具执行链路，就应得到一致的权限判定和回灌结构。

- N8: 安全默认
  对无法可靠判断安全性的调用，系统应选择 Ask 或 Deny，而不是 Allow。未知工具、未知类别、缺少必要参数、参数格式错误、路径解析失败和规则格式异常都不得静默放行。

- N9: 可解释性
  每次 Ask 或 Deny 都应有面向用户和模型可理解的原因，至少说明触发来源，例如 blacklist、sandbox、rule、mode 或 user。原因文本应避免泄漏敏感本地信息；路径可以显示为项目相对路径，必要时显示经规整后的目标摘要。

- N10: 可扩展性
  新增一档权限模式、一类工具分类、一种规则匹配器或一层防御时，应尽量局部修改权限模块，不要求修改 provider 适配层，也不要求把规则散落到各个工具实现中。

- N11: 可测试性
  黑名单匹配、符号链接逃逸、规则匹配、三层优先级、模式矩阵、会话临时规则、人在回路选择结果、拒绝回灌和取消行为，都应能通过自动化测试或可重复的集成场景验证。

- N12: 项目规范
  改动应符合项目现有 Go 代码风格，通过格式化、编译和测试。新增配置文件路径、示例或本地权限文件应避免把用户私有授权规则误提交到版本库。

- N13: 范围克制
  本章只实现本地工具权限判定与交互确认，不引入网络访问控制、资源配额、审计日志、外部策略服务或非内置工具权限模型。

## 不做的事

- 不做网络请求限制、资源配额、速率限制、CPU 限制、内存限制或执行时长配额。
- 不做权限审计日志，不把每次权限决策落地为持久化审计流水。
- 不提供黑名单配置、黑名单关闭开关或用户扩展黑名单机制。
- 不自动泛化人在回路的永久允许规则；永久允许只生成该次调用的精确匹配 allow 规则。
- 不覆盖非内置工具、外部 MCP 工具或未来插件工具的权限模型。
- 不对命令执行类工具做路径沙箱或命令语义级文件访问分析。
- 不支持多项目根、额外授权目录或运行时追加可访问目录。
- 不实现权限规则的图形化编辑器或交互式规则管理界面。
- 不实现除 strict、default、acceptEdits、bypassPermissions 之外的自定义权限模式。
- 不改变 provider API、模型路由、工具调用协议或系统提示缓存策略。

## 验收标准

- AC1: (F1, N1) 命令执行类工具请求执行 `rm -rf /` 及等价高危变体时，系统在执行前判 Deny，真实命令不运行，回灌结果包含 blacklist 来源；在 bypassPermissions 模式和显式 allow 规则存在时仍然被拦截。
- AC2: (F2, N2) 文件工具读取或写入项目根之外路径时被判 Deny；通过项目内软链接指向项目外目标时被判 Deny；项目内尚不存在的新建路径可以通过最近已存在祖先目录判断并正常进入后续权限层。
- AC3: (F3) 规则 `Bash(git status)` 只匹配完整命令 `git status`；规则 `Bash(git *)` 匹配 git 子命令；规则 `Write(src/**)` 匹配 `src/` 下任意写入目标但不匹配 `docs/` 下目标。
- AC4: (F3) 友好名 Bash、Read、Write、Edit、Glob、Grep 分别正确映射到命令执行、读文件、写文件、编辑文件、按模式找文件、搜内容工具。
- AC5: (F4, F8) 会话级临时规则优先于本地级，本地级优先于项目级，项目级优先于用户级；同一层 deny 优先于 allow；构造冲突规则时裁决符合该顺序。
- AC6: (F4, N6) 三层配置文件缺失时系统按空规则集和 default 模式运行；任一配置文件格式非法时，该文件被跳过，其余层继续生效，系统不 panic、不额外放开权限。
- AC7: (F5) 规则未命中时，strict 对只读、文件写和命令执行都返回 Ask；default 对只读返回 Allow、对文件写和命令执行返回 Ask；acceptEdits 对只读和文件写返回 Allow、对命令执行返回 Ask；bypassPermissions 对三类工具返回 Allow，但不能绕过黑名单或沙箱。
- AC8: (F5, F9) 计划工作流仍只向模型暴露只读工具并注入计划提醒；如果防御性地遇到文件写或命令执行请求，模式兜底为 Ask。
- AC9: (F6) 黑名单命中后不再进入沙箱、规则、模式或人在回路；显式 deny 规则命中后不再进入模式；显式 allow 规则命中后直接放行，不再进入模式或人在回路。
- AC10: (F6) 不适用层不会误拦：非命令执行工具跳过黑名单后继续进入沙箱和规则；命令执行工具跳过路径沙箱后继续进入规则和模式。
- AC11: (F7) Ask 时 TUI 展示待确认工具名、关键参数、触发原因和选项；选择允许本次后仅当前调用放行；选择允许本会话后当前会话同一精确调用可自动放行；选择永久允许后本地级配置写入精确 allow 规则；选择拒绝本次后 Deny 回灌且 Loop 继续。
- AC12: (F7, N5) 人在回路等待期间取消当前轮后，程序不死锁，不泄漏等待中的工具执行，下一轮对话仍可继续，历史中的工具调用和工具结果配对合法。
- AC13: (F9) 用户切换权限模式后，TUI 常驻显示当前模式；切换只影响后续调用，不改变已加载规则；模式跨轮保持，不因一次回复结束而重置。
- AC14: (F10, N3) 单批多个工具调用中，被拒绝的调用返回结构化错误结果，被允许的调用正常执行；所有结果按原调用 ID 和顺序回灌，Agent Loop 继续运行。
- AC15: (F11, N7) 对 Anthropic、OpenAI 和 OpenAI 兼容接口运行同样的工具调用场景时，权限判定、Ask/Deny/Allow 结果和回灌结构一致，provider 适配层不承担权限判断。
- AC16: (F12, N8) 未知工具、参数 JSON 无法解析、路径无法规整或工具类别不明时不会静默 Allow；系统返回 Deny 或进入 Ask，并给出可解释原因。
- AC17: (N4) 一批只读工具调用在规则或模式明确 Allow 时仍可并发执行，不弹出人在回路确认；权限检查不把只读批次退化为串行执行。
- AC18: (N9) 每次 Ask 或 Deny 的用户展示和模型回灌都包含权限来源和简短原因，且不输出 API key、认证 token 或敏感环境变量。
- AC19: (N10) 新增一档权限模式或一层防御时，主要改动集中在权限模块；provider 适配层不需要跟随修改。
