# 权限系统 Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为；括号内为验证方式与对应需求。函数、类型或文件名只用于定位，验收以行为为准。

## 实现完整性

- [ ] 黑名单硬拦截：危险命令如 `rm -rf /`、`rm -fr ~`、fork bomb、写块设备命令在执行前被判 Deny，真实命令不运行，拒绝结果包含 blacklist 来源。（验证：权限单测对这些命令断言 Deny；Agent 集成测试断言未调用真实工具且回灌 `permission_denied`。对应 AC1/F1/N1）
- [ ] 黑名单不可绕过：在 bypassPermissions 模式下，黑名单命令仍判 Deny；显式 allow 规则或会话 allow 规则不能放开黑名单。（验证：权限引擎单测在 bypass 和 allow 规则同时存在时仍对危险命令断言 Deny。对应 AC1/F1/N1）
- [ ] 沙箱围栏：文件类工具访问项目根之外路径如 `/etc/passwd`、`../outside` 时判 Deny，项目内路径继续进入后续权限层。（验证：权限单测用临时项目根构造内外路径并断言裁决。对应 AC2/F2/N2）
- [ ] 沙箱防软链接逃逸：项目内软链接指向项目外目录或文件时，对该软链接路径的文件操作判 Deny。（验证：权限单测创建项目内 symlink 指向外部临时目录，断言先解析符号链接再比对项目根。对应 AC2/F2/N2）
- [ ] 新建路径祖先回退：项目内尚不存在的新建文件路径，包括未创建的多级中间目录，不因目标不存在被误拒。（验证：权限单测对项目内新路径断言通过沙箱，并继续进入规则或模式层。对应 AC2/F2/N2）
- [ ] 规则精确匹配：`Bash(git status)` 只匹配 `git status`，不匹配 `git push`。（验证：规则或引擎单测构造规则和命令调用断言命中/未命中。对应 AC3/F3）
- [ ] 规则 glob 匹配：`Bash(git *)` 匹配 git 子命令；`Write(src/**)` 匹配 `src/a/b.go`，不匹配 `docs/x`。（验证：规则或引擎单测断言命令 glob 和路径 glob 行为。对应 AC3/F3）
- [ ] deny 规则拦截：单独 deny 规则如 `Bash(git push)` 命中时判 Deny。（验证：引擎单测构造 deny 规则并断言拒绝。对应 AC3/F3）
- [ ] 同层 deny 优先：同一层 allow 和 deny 都命中时，最终裁决为 Deny。（验证：规则集单测或引擎单测构造冲突规则。对应 AC5/F4）
- [ ] 友好名路由：Bash、Read、Write、Edit、Glob、Grep 正确作用到 `run_command`、`read_file`、`write_file`、`edit_file`、`find_files`、`search_code`。（验证：权限单测为六个友好名分别构造规则和工具调用，断言命中。对应 AC4/F3）
- [ ] 权限模式矩阵：strict 对只读/文件写/命令执行均 Ask；default 对只读 Allow、文件写和命令执行 Ask；acceptEdits 对只读和文件写 Allow、命令执行 Ask；bypassPermissions 对三类工具 Allow，但不能绕过黑名单或沙箱。（验证：模式矩阵单测逐档逐类断言裁决。对应 AC7/F5）
- [ ] 计划工作流兼容：`/plan` 或计划工作流仍只向模型暴露只读工具并注入计划提醒；防御性遇到文件写或命令执行请求时不会静默放行。（验证：Agent 测试断言 plan 请求工具定义只有只读工具，且非只读请求进入 Ask 或被拒。对应 AC8/F5/F9）
- [ ] 流水线短路：黑名单命中后不进入沙箱、规则、模式或人在回路；显式 deny 规则命中后不进入模式；显式 allow 规则命中后不进入模式或人在回路。（验证：引擎单测构造可观察来源的冲突场景，断言最终来源和裁决。对应 AC9/F6）
- [ ] 不适用层正确跳过：非命令执行工具不会被黑名单误拦；命令执行工具不会进入路径沙箱，而是继续进入规则和模式层。（验证：引擎单测分别构造文件工具和命令工具，断言来源与裁决。对应 AC10/F6）
- [ ] 安全默认：未知工具、参数 JSON 无法解析、文件类缺少路径、类别无法判断时不静默 Allow；系统返回 Deny 或 Ask，并给出原因。（验证：引擎单测对畸形调用逐项断言不返回 Allow。对应 AC16/F12/N8）

## 集成

- [ ] 拒绝回灌不中断：被权限拒绝的工具调用作为错误工具结果回灌，Agent Loop 继续进入下一轮模型请求。（验证：Agent fake provider 测试首轮请求被拒工具，断言 conversation 中有错误工具结果且 provider 收到次轮请求。对应 AC14/F10/N3）
- [ ] 保序配对回灌：同一批工具调用中，被拒调用和放行调用按原调用顺序与各自调用 ID 回灌，不串位。（验证：Agent 单测构造混合批，断言结果顺序、call ID 和错误状态。对应 AC14/F10/N3）
- [ ] 人在回路四选项：default 下文件写触发审批；允许本次会执行且不留规则；允许本会话会执行并写入会话规则；永久允许会执行并写入本地配置；拒绝本次会回灌拒绝结果。（验证：Agent 单测通过审批通道回传四种选择并断言行为。对应 AC11/F7/F8）
- [ ] 永久允许持久化：选择永久允许后，本地级配置文件出现精确 allow 规则；重建引擎后同一调用自动 Allow。（验证：权限持久化单测断言文件内容和重载后的裁决。对应 AC11/F7）
- [ ] 会话允许不落盘：选择允许本会话后，当前引擎后续同一精确调用自动 Allow；重建引擎后该会话规则消失。（验证：权限或 Agent 单测断言内存生效、磁盘文件无新增规则、重载后不保留。对应 AC5/F8）
- [ ] 层级优先级：会话级盖过本地级，本地级盖过项目级，项目级盖过用户级；同层 deny 优先 allow。（验证：引擎单测构造四层冲突规则断言裁决。对应 AC5/F4/F8）
- [ ] 配置降级：三层配置文件缺失时按空规则集和 default 模式运行；某层 YAML 非法时跳过该层，其余层继续生效，引擎不 panic、不额外放开权限。（验证：配置和引擎单测传入缺失/非法文件断言 load issue 与裁决。对应 AC6/F4/N6）
- [ ] 启动默认模式：本地级、项目级、用户级的 `defaultMode` 按本地 > 项目 > 用户生效；都未配置时为 default。（验证：配置单测分别设置三层默认模式断言 `StartMode`。对应 AC6/F4）
- [ ] 只读并发不退化：明确 Allow 的连续只读调用仍并发执行；被 Deny 的只读调用生成错误结果，其余 Allow 调用继续完成；不需要确认的只读批次不弹审批。（验证：Agent 单测用慢只读假工具或事件顺序断言并发和结果齐备。对应 AC17/N4）
- [ ] 审批取消安全：人在回路等待期间取消当前轮后，Agent 停止等待，TUI 回到空闲，可继续下一轮；无死锁或 goroutine 泄漏。（验证：Agent 和 TUI 测试在审批等待中 cancel/Esc，使用超时保护和 race 测试。对应 AC12/F7/N5）
- [ ] 权限模式切换：idle 态连续 Shift+Tab 按 strict -> default -> acceptEdits -> bypassPermissions -> strict 循环；切换只影响后续调用，不改变规则。（验证：TUI 单测模拟按键，断言模式序列和规则对象不变。对应 AC13/F9）
- [ ] 模式跨轮保持：切换权限模式后发起新一轮对话，权限模式保持上次值，不因本轮结束重置。（验证：TUI 单测切换后 submit，再完成一轮，断言模式不变。对应 AC13/F9）
- [ ] 状态栏常驻模式：状态栏左侧显示 `STRICT`、`DEFAULT`、`ACCEPT EDITS` 或 `BYPASS`，不显示 provider 名；计划工作流标识不覆盖权限模式。（验证：TUI 视图单测检查状态栏文本。对应 AC13/F9）
- [ ] 跨 provider 一致：权限判定在 Agent 层完成，provider 适配层无权限逻辑；Anthropic、OpenAI 和兼容 base URL 的同类工具调用得到一致 Allow/Ask/Deny 行为。（验证：代码 diff 检查 provider 包无 permission 依赖；用 fake 或实际 provider 配置运行同类场景。对应 AC15/F11/N7）
- [ ] 可解释原因：每次 Ask 或 Deny 的 TUI 展示和工具回灌包含来源和简短原因，如 blacklist、sandbox、rule、mode 或 user。（验证：单测断言审批请求和拒绝工具结果 metadata/content 含来源与原因。对应 AC18/N9）
- [ ] 不泄漏敏感信息：权限原因、配置加载提示、TUI 展示和工具回灌不输出 API key、认证 token 或敏感环境变量。（验证：单测或手工检查带敏感配置的输出；`rg -n "api_key|token" test-output` 无泄漏。对应 AC18/N9/N12）
- [ ] 可扩展性边界：新增模式、规则匹配器或防御层时主要改动集中在 permission 包；provider 适配层不需要跟随修改。（验证：review diff 范围，确认 provider 包无改动。对应 AC19/N10）
- [ ] Part_4/Part_5 既有行为不退化：普通聊天、Agent Loop 多轮工具调用、用户取消、工具错误恢复、历史继续对话、计划模式提醒和缓存相关用量事件仍可运行。（验证：既有测试通过，并运行关键 smoke 场景。对应 AC20/N3）

## 端到端场景

- [ ] 场景 1：default 写文件需确认。启动 PseudoClaude，在 default 模式下让模型写一个项目内新文件，应弹出审批块；选择“允许本次”后文件被写入，Agent Loop 继续。（验证：TUI 实跑观察审批块、文件存在和后续回复。对应 AC11/F7）
- [ ] 场景 2：允许本会话复用。对某个写文件调用选择“允许本会话”，随后让模型再次执行同一精确调用，应不再弹窗；重启 PseudoClaude 后该放行不再保留。（验证：TUI 实跑两次调用并重启观察。对应 AC5/F8）
- [ ] 场景 3：永久允许持久化。对某个命令或写文件调用选择“永久允许”，本地权限文件出现精确 allow 规则；重启后同一调用直接执行。（验证：查看 `.PseudoClaude/permissions.local.yaml` 并重启复测。对应 AC11/F7）
- [ ] 场景 4：拒绝后模型调整。让模型写项目外路径，系统回灌 sandbox 拒绝原因；模型后续改为项目内合法路径并完成任务，Loop 未终止。（验证：TUI 实跑观察拒绝结果和后续安全替代方案。对应 AC14/F10）
- [ ] 场景 5：菜单交互。审批块默认高亮“允许本次”；上下键或 `j/k` 能移动；Enter 确认；数字键 1/2/3/4 分别对应允许本次、允许本会话、永久允许、拒绝本次。（验证：TUI 实跑逐项选择。对应 AC11/F7）
- [ ] 场景 6：strict 模式。切到 strict 后，只读、写文件和命令执行都触发审批或拒绝，不静默放行。（验证：TUI 实跑只读、写入、命令三类调用。对应 AC7/F5）
- [ ] 场景 7：acceptEdits 模式。切到 acceptEdits 后写/改项目内文件不弹窗直接执行，命令执行仍需要确认。（验证：TUI 实跑写文件与 `go test` 命令。对应 AC7/F5）
- [ ] 场景 8：bypassPermissions 模式。切到 bypassPermissions 后普通项目内写入和普通命令不弹窗；危险命令如 `rm -rf /` 仍被黑名单拦截。（验证：TUI 实跑普通调用和危险命令拦截。对应 AC1/AC7/N1）
- [ ] 场景 9：沙箱拦截。让模型读 `/etc/passwd` 或写 `../outside`，系统拒绝并展示“路径在项目目录之外”或等价原因。（验证：TUI 实跑观察拒绝工具结果。对应 AC2/F2）
- [ ] 场景 10：计划工作流不变。使用 `/plan <任务>` 时只读探索并产出计划；使用 `/do` 时按计划执行，计划提醒与工具可见性符合既有行为。（验证：TUI 实跑 `/plan` 和 `/do`，观察只读工具和执行切换。对应 AC8/F9）
- [ ] 场景 11：审批取消。审批块出现时按 Esc 或 Ctrl+C 取消当前轮，程序不退出；随后发送新消息可继续对话，不出现 provider 历史错误。（验证：TUI 实跑取消后继续对话。对应 AC12/N5）
