# Agent 工具系统 Spec

## 背景

PseudoClaude 已经完成了多协议 LLM 终端对话客户端的第一阶段能力：用户可以在终端中选择 provider、发送消息、接收流式回复，并在单次进程内保留多轮文本上下文。

当前系统仍然只是一个“会说话”的聊天客户端。模型即使知道应该查看文件、修改代码或运行命令，也只能给出文字建议，不能直接操作本地工作区。本阶段要引入工具系统，让模型能够在用户提问后请求执行受支持的本地工具，程序负责执行工具，并把结构化结果回灌到对话历史中，使后续章节可以在此基础上发展出完整 Agent Loop。

## 目标

- 让模型能够通过协议原生的工具调用机制请求本地能力，而不再只能输出文本建议。
- 提供一套统一的工具描述、参数校验、执行和结果返回机制，供不同工具复用。
- 先实现六个核心本地工具：读文件、写文件、改文件、执行命令、按模式找文件、搜代码内容。
- 将工具注册、工具列表转换、工具调用解析、工具执行和结果回灌接入现有 LLM 流式流程。
- 对工具执行失败、参数错误、超时和不可安全处理的情况返回结构化错误，让模型能够理解失败原因。
- 明确本阶段只支持“一次模型回复中出现工具调用后执行并回灌结果”，不自动继续下一轮模型推理。

## 功能需求

- F1: 工具统一描述
  系统提供统一的工具抽象。每个工具都必须声明可供模型识别的名称、自然语言描述、参数结构说明，并能接收一组参数后执行本地操作，返回结构化结果。工具名称在注册范围内必须唯一。

- F2: 核心工具集合
  系统内置六个核心工具：
  1. 读文件：读取指定文本文件内容并返回。
  2. 写文件：向指定路径写入完整文件内容，必要时创建文件。
  3. 改文件：在指定文件中用新文本替换唯一匹配的旧文本。
  4. 执行命令：在当前工作目录上下文中运行命令并返回输出。
  5. 按模式找文件：根据 glob 风格模式列出匹配路径。
  6. 搜代码内容：根据文本或正则模式搜索文件内容并返回匹配位置摘要。

- F3: 工具注册中心
  系统提供集中注册和查找工具的能力。启动时登记内置工具，请求模型前能按当前 provider 协议转换成 API 可识别的工具定义列表；收到工具调用时能按名称找到对应工具，找不到时返回结构化错误。

- F4: 工具参数处理
  系统在执行工具前解析并校验模型提供的参数。参数不是合法 JSON、缺少必要字段、字段类型不符或参数语义无效时，不执行工具操作，并把可读的结构化错误返回给模型。

- F5: 工具执行结果结构化
  每次工具执行都返回统一结构，至少能表达是否成功、面向模型的结果内容、错误类型、错误消息以及必要的补充信息。成功与失败都必须能被追加到对话历史中，供模型后续理解。

- F6: 超时与错误处理
  所有工具执行都受超时控制。执行过程中发生文件系统错误、命令错误、上下文取消、超时或内部异常时，系统不得崩溃；应把失败包装为结构化结果，并保留足够信息帮助模型调整下一步请求。

- F7: 文件读写边界
  文件类工具以当前工作目录为默认操作上下文，支持相对路径和可解析的本地路径。路径不存在、路径指向目录、权限不足、文件不可读写或内容不适合按文本处理时，返回清晰错误。

- F8: 改文件唯一匹配
  改文件工具必须使用“旧文本原文唯一匹配替换”的行为：当旧文本在目标文件中正好出现一次时才执行替换；出现零次或多次时都不修改文件，并返回明确错误说明匹配数量，让模型能够重试。

- F9: 命令执行行为
  执行命令工具应在当前工作目录上下文中运行，捕获标准输出、标准错误和退出状态。命令超时或非零退出时，仍以工具结果形式返回可观察输出，而不是中断整个会话。

- F10: 流式工具调用解析
  LLM 客户端在流式响应中既能继续解析普通文本增量，也能解析工具调用增量。对于工具调用的 JSON 参数碎片，系统必须按调用标识进行拼接，直到该工具调用完整结束后再尝试解析参数。

- F11: 跨协议工具调用适配
  Anthropic 与 OpenAI 协议都应通过统一上层事件表达“文本增量、工具调用开始/参数增量/工具调用完成、完成、错误”等结果。协议差异限制在各自适配层内，上层执行工具时不依赖具体 provider。

- F12: 工具调用回灌
  当模型请求工具时，系统执行该工具，并把工具调用记录与工具结果按当前 provider 协议要求追加回对话历史。结果应包含工具调用标识，使模型能够把结果对应回原工具请求。

- F13: 单次工具调用回合边界
  本阶段在一次用户提交后，模型如果请求工具，系统执行工具并回灌结果后即结束本轮用户可见处理；不自动再次请求模型生成基于工具结果的最终回答。用户下一次输入或后续章节的 Agent Loop 再触发下一轮模型推理。

- F14: TUI 可见反馈
  当模型请求工具、工具正在执行、工具执行成功或失败时，终端界面应给出可区分的状态反馈。普通文本回复仍按既有流式体验展示；工具失败不应导致 TUI 退出。

## 非功能需求

- N1: 协议一致性
  无论使用 Anthropic 还是 OpenAI 协议，用户感知到的工具执行、错误反馈和会话继续能力应保持一致。

- N2: 稳定性
  工具参数错误、未知工具、执行失败、超时、模型流式事件异常或 provider 返回不完整参数时，程序应以错误结果或错误事件结束当前处理，不得 panic 或破坏终端状态。

- N3: 可观测性
  工具结果和错误应包含足够的上下文信息，便于用户和模型理解发生了什么；但不得泄露 API 密钥等敏感配置。

- N4: 响应性
  工具执行和 LLM 流式接收不得阻塞 TUI 渲染。长时间执行的工具应显示进行中状态，并能响应已有的取消机制。

- N5: 输出可控
  文件读取、搜索结果和命令输出应避免无限制扩大内存或刷屏。超出合理输出范围时，系统应截断并在结果中标明截断事实。

- N6: 可测试性
  工具抽象、注册查找、参数校验、文件修改唯一匹配、命令超时和流式参数拼接等关键行为应能通过自动化测试验证。

- N7: 向后兼容
  没有发生工具调用时，原有纯文本聊天、流式输出、多轮上下文和错误展示行为应保持不变。

## 不做的事

- 自动 Agent Loop：本阶段不在工具结果回灌后自动再次调用模型生成后续回答。
- 多轮工具链规划：不实现“模型连续调用多个工具直到完成任务”的循环控制。
- 权限确认系统：本阶段不做逐工具、逐路径或逐命令的用户确认弹窗。
- MCP 集成：不连接外部 MCP server，也不加载第三方工具。
- 沙箱或容器隔离：命令执行不引入容器、虚拟机或系统级沙箱。
- 长期记忆和会话持久化：工具调用与结果只进入当前进程内会话历史，不落盘保存历史。
- 二进制文件处理：核心文件工具面向文本内容，不提供图片、压缩包等二进制读写编辑能力。
- 复杂补丁算法：改文件只做原文唯一匹配替换，不做 diff/patch 合并、模糊匹配或自动冲突解决。
- 工具市场或插件系统：本阶段只内置固定六个工具，不提供用户动态安装工具。
- 用量统计和成本展示：不统计工具执行耗时之外的 token、费用或资源消耗明细。

## 验收标准

- AC1: (F1) 每个内置工具都能暴露名称、描述和参数结构说明；重复工具名称会被拒绝或产生清晰错误。
- AC2: (F2) 六个核心工具均可被注册并单独执行：读文件、写文件、改文件、执行命令、按模式找文件、搜代码内容。
- AC3: (F3) 请求模型前，注册中心能生成当前 provider 可识别的工具定义列表；收到未知工具名时返回结构化错误。
- AC4: (F4) 工具参数不是合法 JSON、缺少必填字段或类型不匹配时，工具不会执行，并返回可读错误结果。
- AC5: (F5) 工具成功和失败都以统一结构返回，且可被追加进对话历史供后续请求携带。
- AC6: (F6) 构造一个超时工具场景时，程序不中断会话，返回包含超时原因的工具错误结果。
- AC7: (F7) 读不存在文件、写无权限路径、读取目录等边界情况会返回清晰错误，而不是崩溃。
- AC8: (F8) 改文件在旧文本正好出现一次时完成替换；出现零次或多次时文件保持不变，并返回匹配数量相关错误。
- AC9: (F9) 执行成功命令时返回标准输出；执行非零退出命令时返回退出状态、标准输出和标准错误；执行超时命令时返回超时错误。
- AC10: (F10) 对流式到达的工具调用参数碎片，系统能正确拼接为完整 JSON 后再执行；不完整或损坏 JSON 会进入参数错误路径。
- AC11: (F11) Anthropic 与 OpenAI 两种协议都能把工具调用转换为统一上层事件，工具执行层不依赖具体 provider 类型。
- AC12: (F12) 工具调用记录和工具结果能按 provider 要求追加回历史；下一次请求模型时能携带该工具结果上下文。
- AC13: (F13) 一次用户提交中，工具执行和结果回灌完成后不会自动发起第二次模型请求；界面回到可输入状态。
- AC14: (F14) TUI 在工具调用开始、执行中、成功和失败时都有可观察反馈；工具失败后用户仍可继续输入下一轮。
- AC15: (N1, N7) 未触发工具调用的普通文本对话行为与 Part 1 保持一致，包括流式显示、markdown 定型和错误展示。
- AC16: (N5) 当文件内容、搜索结果或命令输出超过限制时，返回内容会被截断，并明确标记已截断。
